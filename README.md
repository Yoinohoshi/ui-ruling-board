# ui-ruling-board

UI の配置や見た目を、用意した画像で比べて 1 項目ずつ裁定するための、依存のない比較 HTML。

- 画像は利用者が用意して置く。閲覧する器は画像を作らない。開発用の準備コマンドで、撮影済み画像の差と撮り直しを検査し、拡大画像を生成できる。
- 1 つの問いに 1 つの答え。項目ごとに 1 案（または保留）を選び、その場でコメントを書く。
- 左の目次に、項目ごとの未選択 ○・選択済 ●・保留 ◐ と進み具合が出る。
- 比べる案は同じ枠の中で切り替える（←→・数字）。並べて見ることもできる。
- 答えは Markdown の回答案として書き出す。
- ビルド不要。`index.html` をダブルクリックで開く（file://）。外部への通信をしない。

## 使い方

**0.3.0：r6 型の回を準備・検査・発行する手順は [発行ガイド](docs/PUBLISHING.md)。**
項目定義からの生成、guard と show の分離、名指し拡大、撮り直しの画素一致、画像・並び・版の検査、配布先での file:// 確認を一括で実行する。
完成済みの回は `npm run publish:round -- <回のフォルダ> <新しい配布先>` で発行する。発行は検査済みのローカル配布フォルダの作成（ネットワークへのアップロードはしない）。

### 1. 回のフォルダを作る

器を回のフォルダへコピーする。回ごとにコピーするので、答え終えた回は器の更新に巻き込まれない。

```sh
node scripts/install.mjs path/to/round-1
```

```
round-1/
  index.html  board.js  board.css  validate.js   器のコピー（手で書き換えない）
  board.lock.json                                器の版・コミット・各ファイルの sha256
  round.js                                       記述（自分で書く）
  images/                                        画像（自分で置く）
```

- すでに `board.lock.json` がある所へは入れない。入れ直すときは `--force`。
- `node scripts/install.mjs --check path/to/round-1` で、コピーが錠と同じか確かめる（違えば終了コード 1）。

### 2. 画像を置く

形式は png・jpg・webp・svg。置き場は自由（記述から相対パスで指す）。既定の規則を決めておくと、記述に 1 枚ずつ書かずに済む。

```
images/D1.1/cur-1440.png
images/D1.1/a-1440.png
images/D1.1/a-390.png
```

### 3. 記述を書く（`round.js`）

```js
RulingBoard.define({
  schema: 1,
  round: { id: "settings-r1", title: "設定画面の配置" },
  views: [
    { id: "1440", label: "1440" },
    { id: "390", label: "390" },
  ],
  images: "images/{item}/{option}-{view}.png",
  decisions: [
    {
      id: "D1",
      title: "詳細の置き場",
      items: [
        {
          id: "D1.1",
          title: "登録の詳細",
          question: "詳細をどこに置くか",
          options: [
            { id: "cur", label: "現状" },
            { id: "a", label: "右の列", recommended: true },
          ],
        },
      ],
    },
  ],
});
```

書いたら確かめる（記述の誤り、画像のファイルの有無、形式どおりの中身か）。

```sh
node scripts/check-round.mjs path/to/round-1/round.js
```

### 4. 開く

`index.html` を開く。同じフォルダの `round.js` を読む。別の記述は `index.html?round=<相対パス>` で開ける。

例：`board/index.html?round=../examples/basic/round.js`

記述に誤りがあれば、本文を描かずに誤りの一覧（場所付き）だけを出す。

## 記述の形（schema 1）

並びの正本は配列の順だけ。見出し・目次・選択欄・回答案の並びと番号は、すべてここから振る。

| 場所          | キー                      | 必須 | 中身                                                                      |
| ------------- | ------------------------- | ---- | ------------------------------------------------------------------------- |
| 頭            | `schema`                  | ○    | `1`                                                                       |
|               | `round`                   | ○    | 回（下）                                                                  |
|               | `views`                   | ○    | 見え方の配列。表示の順                                                    |
|               | `images`                  |      | 画像の規則。`{decision}`・`{item}`・`{option}`・`{view}` を差し込む       |
|               | `decisions`               | ○    | 裁定点の配列                                                              |
| `round`       | `id`                      | ○    | 下書きの鍵と回答案の名前に使う                                            |
|               | `title`                   | ○    | 回の題                                                                    |
|               | `answerTo`                |      | 回答先（回答案に載る）                                                    |
|               | `source`                  |      | 比較元の識別（回答案に載る）                                              |
|               | `created`                 |      | 作った日                                                                  |
| `views[]`     | `id`・`label`             | ○    | 幅や状態（例 `390-open` / `390 · 開`）                                    |
| `decisions[]` | `id`・`title`             | ○    | 裁定点                                                                    |
|               | `note`                    |      | 回答案にだけ載せる注記                                                    |
|               | `items`                   | ○    | 項目の配列（1 つ以上）                                                    |
| `items[]`     | `id`・`title`・`question` | ○    | 項目。`id` は回の中で一意                                                 |
|               | `views`                   |      | この項目の見え方（無ければ回の全部）。先頭の見え方で開く                  |
|               | `focus`                   |      | 見え方ごとの変わる範囲 `[x, y, 幅, 高さ]`（画像の px。最初の段に重ねる）  |
|               | `options`                 | ○    | 案の配列（2 つ以上）                                                      |
| `options[]`   | `id`・`label`             | ○    | 案                                                                        |
|               | `recommended`             |      | `true` で推奨（1 項目に 1 つまで）                                        |
|               | `tags`                    |      | 短い札の配列（例 `["見直し候補"]`）                                       |
|               | `images`                  |      | 見え方ごとのパス。配列なら段（縦に長い画面の続き）。規則より優先          |
|               | `focus`                   |      | この案の変わる範囲（形は項目の `focus` と同じ）。その見え方で項目より優先 |
|               | `noImage`                 |      | `true` で画像を持たない案                                                 |

- `id` は英数字と `.` `_` `-`（先頭は英数字）。
- 知らないキー・id の重複・画像の欠け・推奨の誤りは誤りとして止める（黙って捨てない）。
- 画像のパスは記述のファイルのあるフォルダからの相対パス。
- 値を選択肢にしない。条件は項目のコメントに書く。
- 変わる範囲は、表示中の案の `focus` を、無ければ項目の `focus` を破線で描く。
- 0.2.0 で足したのは案の `focus` だけ（schema は 1 のまま。0.1.0 の記述はそのまま読める。案の `focus` を書いた記述は 0.1.0 の器では「知らないキー」になる）。

## 画面とキー操作

| 操作             | 効き方                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------- |
| 頭の見え方       | 選んだ見え方を、それを持つ項目に出す。持たない項目と「項目ごと」は、項目の最初の見え方 |
| 項目の見え方     | その項目だけを替える                                                                   |
| 切り替え・並べる | 1 枠で替えるか、案を並べるか（覚えておく）                                             |
| ← →              | 比較の枠に焦点があるとき、前後の案へ（端で回る）                                       |
| 1〜9             | 比較の枠に焦点があるとき、その番目の案へ                                               |
| 画像を押す       | 原寸で開く。中でも ← → ・数字で替わる。Esc で閉じる                                    |
| 選択欄           | 案を選ぶと表示もその案に替わる。表示を替えても選択は変わらない                         |

- 開いた直後は、各項目が自分の最初の見え方で出る（頭の見え方は「項目ごと」）。
- 頭の見え方は選択の一覧。見え方がいくつあっても頭の帯の高さは変わらない。
- 狭い幅（900px 未満）では、目次は頭の「目次」ボタンから開く。
- 選択・コメント・見た見え方は、ブラウザに下書きとして残る。記述が 1 字でも変わると、前の下書きは戻さない。

## 回答案の形

```
# 回答：設定画面の配置（settings-r1）
回答先: https://example.com/rounds/1
比較元: v1.2.0 / 記述: 9f3c2a1b / 器: ui-ruling-board 0.3.0
回答日: 2026-10-21 · 選択 2/3（保留 1）

## D1 詳細の置き場
- D1.1 登録の詳細: ② 右の列（推奨 ②） · 見た: 1440, 390
  - コメント: 送りの位置は今のまま
- D1.2 構成の詳細: 保留 · 見た: 1440
- D1.3 実装の詳細: 未選択 · 見た: なし
```

- 「見た」は、その項目の比較の枠の半分以上を画面に出したときと、拡大で開いたときの見え方。
- 「記述」は記述のハッシュ（取り違えを防ぐためのもので、改ざんの検知ではない）。
- ［コピー］でクリップボードへ、［保存］で `<round.id>-answer.md` に保存する。

## file:// の注意

- 記述は `.js`（`RulingBoard.define(...)` の 1 呼び出し）。file:// では `fetch` で JSON を読めないため。
- 器は通常の script。`type="module"` は file:// で止められるため使わない。
- 下書きはブラウザの localStorage に残る。file:// の localStorage はブラウザによって扱いが違う（使えないときは下書きなしで動く）。
- 確かめているのは Chromium 系のブラウザ。

## 開発

Node は `.nvmrc`（26）。

```sh
npm install
npm run setup   # 試験用の Chromium を入れる
npm test        # Playwright。画面を出さない Chromium で file:// を開く
npm run check   # examples/basic の記述を確かめる
```

画面の schema は 1 のまま。0.1.0・0.2.0 の記述をそのまま開ける。0.3.0 は画面の既存操作を維持し、回の準備と発行のコマンドを追加した。回の器を入れ直す場合は、既存の回答済みの回ではなく新しい回で行う。
