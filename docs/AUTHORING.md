# ローカルの発行用HTML（0.5.0）

発行用HTMLを開き、項目・画像・回答形式・金額を設定して、回答用の単一HTMLを保存できる。発行画面と回答画面は外部通信を行わない。現在の確認対象はデスクトップのChromium（file://）。

## 発行画面を生成する

```sh
npm ci
npm run check
npm test
npm run build:author
```

生成先は `artifacts/author.html`。このファイルだけを別の場所へ移しても使える。`author/index.html` は生成元テンプレートなので、直接開く対象ではない。

発行画面を生成する側にはNodeが必要。生成済みの `author.html` を使う人と、回答用HTMLを開く人にはNode・サーバー・ネットワークは不要。

発行元のコードがGitに未登録・変更中、Git外の展開コピー、親リポジトリにだけ属するコピーの場合はプレビュー専用となり、回答用HTMLの保存を無効にする。入力となる器・発行処理・共用処理の全ファイルが追跡され、変更なしのコミットに対応することを確認してから生成する。ファイルのSHA-256とコミットを発行画面に収録する。

## 操作

1. 最初は「サンプルで試す」で架空画面を開ける。実際の回ではタイトル・ID・比較元を入力し、項目を追加する。
2. 各案の元画像と撮り直し画像を選ぶ。複数画像は選択順に段として扱う。同じファイルを元画像と撮り直しに兼用しない。
3. 各見え方に変更を許す範囲（x, y, 幅, 高さ）を入力する。値は画像の画素単位。初期値は480×300のサンプル用なので、実際の画像に合わせる。
4. 回答者が使う出力形式と既定形式を選ぶ。必要なら金額表示を有効にし、各案の金額を入力する。
5. 「検査してプレビュー」を押す。撮り直し、guard外の差、全案の差、自動/名指し拡大を検査し、画像とコードを内包した回答画面を実際に開く。
6. プレビューを確認し「回答用HTMLを保存」を押す。保存先・完了・取消はブラウザ側で確認する。発行画面はダウンロードを開始しただけで保存成功とは表示しない。
   パスワードと確認を入れて保存すると、パスワードを入れないと開けないHTMLになる（下の「パスワードで封をする」）。

## パスワードで封をする

パスワードを入れて保存すると、内包データ（定義・画像・測定記録・器の出所を含む封筒の全体）を gzip で圧縮してから AES-256-GCM で暗号化し、HTMLには暗号文・パスワード欄・復号処理だけを置く。鍵はパスワードから PBKDF2-SHA-256（ランダムな salt・60万回）で作る。暗号化と復号は `shared/seal.js` を発行画面と回答画面で共用する。保存の前に、作った暗号文を同じパスワードで開き直し、元と一致することを確かめる。プレビューは暗号化する前の内容で行う。

回答画面は開いた直後にパスワードを尋ねる。誤ったパスワードと、暗号文の改変は区別できず、どちらも「パスワードが違うか、データが壊れています」と出して開かない。開いた後は封をしない回と同じに照合・表示する。

圧縮の有無は認証付きデータに含めるので、圧縮の欄を書き換えた封も開かない。圧縮の欄が無い封（0.4.0 の最初の形式）は、圧縮しないものとして開く。

目安（画像454枚・平文の内包データ41.4MBの回、デスクトップ）：封をした内包データは39.7MB、開封はChromium 156・Edge 155で約0.3秒。

境界：

- 強さはパスワードの強さで決まる。配布したファイルには手元で何度でも推測を試せるので、短い・推測しやすいパスワードは使わない。
- 配布後に取り消す手段は無い。開いた人は中身を保存できる。
- 下書き（選択・コメント・見た見え方）はブラウザの localStorage に平文で残る。書き出す回答も平文。
- 封をしたファイルも、実製品の画面や内部の情報を含むなら公開リポジトリへ置かない。
- 暗号化の確認対象は、デスクトップの Chromium と Edge（file://）。Firefox・Safari は未確認。

設定変更後は古い結果を保存できない。再検査が必要。項目の順序、複数の見え方、画像のない案、名指し拡大等は「詳細設定」で項目定義と撮影条件をJSON編集し、適用できる。項目定義と撮影条件の契約は [PUBLISHING.md](PUBLISHING.md) と同じ。

## 設定の保存と読込み

「設定を保存」で、項目定義・撮影条件・元画像・撮り直し画像を含むプロジェクトJSONを保存する。「設定を開く」で再編集できる。設定を変更したら保存する。発行元の設定を自動で永続保存する機能はない。

「撮影元フォルダを開く」では以下を読み込める。

- `items.json`、またはJSONリテラルだけを `export const description = ...;` する `items.mjs`
- `captures.json`
- 撮影条件が参照する画像

任意のmjsを実行しない。importや式を含むmjsは、Node側で独立したJSONへ展開してから読み込む。参照されないファイルは取り込まない。アプリ固有の自動撮影は発行画面の対象外。画像は1ファイル40MB、復号後4000万画素以内。

## 回答形式と金額

schema 1に以下の任意属性を追加する。これらを指定しない旧回の挙動は維持する。新属性のある定義を旧版の器で開くことはできない。

```json
{
  "round": {
    "output": { "formats": ["markdown", "json", "text", "csv"], "default": "markdown" },
    "pricing": { "currency": "JPY" }
  },
  "option": { "price": 1000 }
}
```

上記は属性だけの抜粋。`price` は各 `options[]` に設定する。金額を使わない回は `round.pricing` と `price` を省略する。現在は日本円・0以上の整数に対応し、税や手数料を自動計算しない。空欄は金額未設定、0は0円。保留・未選択・選んだ案の金額未設定は未確定として残す。金額機能を画面で無効にすると価格の設定も取り除く。

合計は実際の回答選択だけを集計する。画像表示だけの切替では変わらない。最下部に合計と未確定数を表示し、出力文字列にも反映する。

JSON出力は `schema: 1`、`round`、`descriptionDigest`、`boardVersion`、`date`、`decisions`、任意の `pricing` を持つ。項目には状態（selected/held/unselected）、選択ID・ラベル、コメント、閲覧した見え方、推奨IDが入る。CSVは1項目1行で、共通情報と集計値を各行に持つ。式として扱われ得るセルには先頭にアポストロフィを付ける。Markdown・テキスト・CSV・JSONは同じ回答状態から生成し、コピー・保存の形式と拡張子を揃える。

## 検査と既知の境界

Nodeの準備処理とブラウザの準備処理は `shared/prepare.js` と `shared/pixels.js` を共用する。出力名の衝突は書込み前に拒否し、拡大比較にも短い案の最終段の繰返しを適用する。

単一HTMLは測定記録・元の項目定義・生成拡大の一覧・器の出所を内包する。撮り直し画像自体や無関係なファイルは配布しない。測定した入力のスナップショットから出力を生成し、定義・画像・測定記録をまとめたSHA-256を起動時に照合する。データの差替え・破損を検出する仕組みで、実行コードを含むHTML全体の署名や悪意ある書換えへの真正性保証ではない。

CLIの従来フォルダ発行に残るIssue #5・#6は別途対応が必要。今回の単一HTML経路の検査をもって、旧経路の問題が解消したとは扱わない。Issue #7〜#10はローカル実装の報告対象とし、公開mainへの反映・受入完了は別途確認する。
